Introduction

Thank you for purchasing Distro Supawave. This documentation will guide you through installing, configuring, and using the platform. Please read through this document fully before starting the installation.

Distro Supawave is a white-label music distribution platform that allows you to run your own distribution service. Artists and labels submit their releases through your platform. You review and approve them, download the metadata package, and manually push to your chosen distributor (CDBaby, Symphonic, DistroKid, etc.). Royalties are imported back via CSV and distributed to artists through an earnings approval workflow.

Live Demo: Visit distrosupawave.hadegoldmedia.com to see the platform in action before installation.

What Is Included

  • Full Laravel 12 source code
  • All migrations and seeders
  • This documentation (HTML)
  • .env.example configuration file
  • All compiled frontend assets
  • Automated copyright scanner (ACRCloud)
Note: The vendor folder is included in the package. You can also run composer install after uploading the files. See the installation section for full instructions.

Server Requirements

Before installing Distro Supawave, make sure your server meets the following requirements:

PHP & Extensions

  • PHP 8.2 or higher
  • BCMath Extension
  • Ctype Extension
  • cURL Extension
  • DOM Extension
  • Fileinfo Extension
  • JSON Extension
  • Mbstring Extension
  • OpenSSL Extension
  • PDO Extension
  • PDO MySQL Extension
  • Tokenizer Extension
  • XML Extension
  • ZipArchive Extension

Server & Database

  • MySQL 5.7+ or MariaDB 10.3+
  • Apache or Nginx web server
  • Composer 2.0+
  • mod_rewrite enabled (Apache)
  • Minimum 512MB RAM
  • Minimum 500MB disk space

Folder Permissions

  • storage/ - writable (755)
  • bootstrap/cache/ - writable (755)
  • public/uploads/ - writable (755)
Distro Supawave is compatible with shared hosting (cPanel), VPS, and dedicated servers. No special server configuration is required beyond the requirements above.

Installation

Distro Supawave includes a web installer that handles the entire setup process for you. Follow these steps carefully.

Step 1 - Upload Files

  1. Download and extract the package ZIP
  2. Extract the ZIP on your server
  3. Move/Copy all extracted files to your server's public_html folder (or your domain's root folder)
  4. You can use FTP (FileZilla), cPanel File Manager, or SSH
Make sure you upload the contents of the folder, not the folder itself. The file must be directly inside public_html.

Step 2 - Run Composer Install

The vendor folder is included. You can install dependencies via Composer before running the installer.

Via SSH (recommended):

cd /path/to/your/public_html
composer install --optimize-autoloader --no-dev

Via cPanel Terminal:
Go to cPanel → Terminal, navigate to your folder and run the same command above.

If your host does not allow SSH, follow Step 1.

Step 3 - Run the Web Installer

Once files are uploaded and Composer has run when necessary, visit your domain in a browser.

https://yourdomain.com/install

The installer has 4 steps:

  1. Requirements Check The installer checks that all required PHP extensions are enabled and that storage folders are writable. All items must show a green checkmark before proceeding. If anything fails, contact your hosting provider.
  2. Database Configuration Enter your database credentials - host (usually localhost), database name, username, and password. Click Test Connection to verify before proceeding.
  3. Site & Email Settings Enter your site name, and support email and SMTP email settings. The site URL must match your actual domain exactly (e.g. https://yourdomain.com).
  4. Admin Account Create your administrator account. Enter your name, email address, and a strong password. This will be the main admin login.
  5. Complete Installation is complete.
Installation complete! Log in at yourdomain.com/admin/login with the credentials you created in Step 5.

cPanel / Shared Hosting (Document Root Fix)

Laravel serves everything from the public/ folder. On cPanel, set the domain’s document root to your project’s public directory: 

Document root: /home/yourusername/yourdomain.com/public

In cPanel: Domains → Manage (your domain) → Document Root and point it at the public folder.

If you cannot change the document root (most shared hosts / LiteSpeed), the package includes two .htaccess files that make everything work automatically. Upload both files — the root one forwards every request into public/, and public/.htaccess serves real files (styles, images, compiled assets) and routes everything else to public/index.php.

1. Root .htaccess (project root, next to artisan)

<IfModule mod_rewrite.c>
RewriteEngine On

# Redirect www → non-www (preserve HTTPS)
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^(.*)$ https://%1/$1 [L,R=301]

</IfModule>

<IfModule mod_rewrite.c>
    <IfModule mod_negotiation.c>
        Options -MultiViews -Indexes
    </IfModule>

    RewriteEngine On

    # Handle Authorization Header
    RewriteCond %{HTTP:Authorization} .
    RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

    # Handle X-XSRF-Token Header
    RewriteCond %{HTTP:x-xsrf-token} .
    RewriteRule .* - [E=HTTP_X_XSRF_TOKEN:%{HTTP:X-XSRF-Token}]

    # Redirect Trailing Slashes If Not A Folder...
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteCond %{REQUEST_URI} (.+)/$
    RewriteRule ^ %1 [L,R=301]

    # Forward every request into public/ (public/.htaccess then serves real
    # files and routes the rest to public/index.php). The !^/public/ guard
    # prevents a rewrite loop.
    RewriteCond %{REQUEST_URI} !^/public/ [NC]
    RewriteRule ^(.*)$ public/$1 [L]

    # Send Requests To Front Controller...
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteRule ^ index.php [L]
</IfModule>

2. public/.htaccess (inside the public/ folder)

<IfModule mod_rewrite.c>
    <IfModule mod_negotiation.c>
        Options -MultiViews -Indexes
    </IfModule>

    RewriteEngine On

    # Handle Authorization Header
    RewriteCond %{HTTP:Authorization} .
    RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

    # Handle X-XSRF-Token Header
    RewriteCond %{HTTP:x-xsrf-token} .
    RewriteRule .* - [E=HTTP_X_XSRF_TOKEN:%{HTTP:X-XSRF-Token}]

    # Redirect Trailing Slashes If Not A Folder...
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteCond %{REQUEST_URI} (.+)/$
    RewriteRule ^ %1 [L,R=301]

    # Serve existing files or directories directly
    RewriteCond %{REQUEST_FILENAME} -f [OR]
    RewriteCond %{REQUEST_FILENAME} -d
    RewriteRule ^ - [L]

    # Send all other requests to the Laravel front controller
    RewriteRule ^ index.php [L]
</IfModule>
Important: upload both files. If only the root .htaccess is present, the site loads but styles/images work while app pages (login, dashboard) return 404. If public/.htaccess is missing its front-controller rule, non-asset pages 404. After uploading, run php artisan optimize:clear and reload.

SMTP Email Configuration

Distro Supawave sends email notifications for release approvals, earnings, and withdrawals. Configure SMTP during installation or update the following values in your .env file:

MAIL_MAILER=smtp
MAIL_HOST=smtp.your-provider.com
MAIL_PORT=587
MAIL_USERNAME=your@email.com
MAIL_PASSWORD=yourpassword
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=noreply@yourdomain.com
MAIL_FROM_NAME="Your Platform Name"
Popular SMTP providers: Mailgun, SendGrid, Amazon SES, Gmail SMTP. For production, avoid using Gmail SMTP as it has sending limits.

File Upload Configuration

For large audio file uploads (WAV files can be 100MB+), make sure your server's PHP limits are configured. Add or update these in your php.ini or .htaccess:

upload_max_filesize = 200M
post_max_size = 200M
max_execution_time = 300
memory_limit = 256M

Or via .htaccess:

php_value upload_max_filesize 200M
php_value post_max_size 200M
php_value max_execution_time 300
php_value memory_limit 256M

If you use Nginx, also raise client_max_body_size to match (e.g. client_max_body_size 200M;). Audio is uploaded in 2MB chunks, but the limit should still comfortably exceed a single chunk.

Release Upload (Artist/Label)

Supported Release Types

  • Single - 1 track
  • EP - 2 to 6 tracks
  • Album - 7 or more tracks

Upload Process

  1. Go to Upload Music from the user dashboard
  2. Select release type (Single, EP, or Album)
  3. Upload cover art - must be 3000×3000px minimum, JPEG or PNG
  4. Fill in release details - title, genre, release date, label name, explicit flag
  5. Upload audio tracks - WAV (preferred) or high-quality MP3
  6. Fill in track details - title, featured artists, producers, ISRC (if known)
  7. Submit for review
Release Date: Release dates must be at least 14 days in the future to give enough time for distribution processing.

Audio Upload

Distro Supawave uses chunked uploading for audio files. Large files (100MB+ WAV files) are split into 2MB chunks and uploaded progressively. This means large files work even on shared hosting with standard PHP upload limits. A progress bar shows the upload status for each track, and any upload errors are surfaced clearly in the interface.

Automatic copyright scan: every uploaded master is fingerprinted by the copyright scanner immediately after the upload finishes. If a match is found, the track is marked blocked and flagged for your review.

Admin Release Management

Release Queue

All submitted releases appear in the admin panel under Music → All Releases. Releases are filterable by status:

  • Pending - Awaiting admin review
  • Approved - Approved for distribution
  • Rejected - Returned to artist with reason

Copyright Column

Every row also shows a Copyright column with the scan result for that release:

  • Flagged - A track matched a copyrighted work; the matched title & artist are shown. Reject the release or investigate before approving.
  • Clear - Every track was scanned and no match was found.
  • Not scanned - The track has not been scanned yet (scanner disabled or still processing).
  • Scan failed - The scan could not complete (e.g. file rejected as too large, no fingerprint). Check the copyright scan records.

See the Copyright Scanner section for configuration.

Approving a Release

  1. Click on a pending release to view full details
  2. Review the cover art, tracks, metadata, and artist information
  3. Click Approve - the artist is notified by email automatically
  4. Download the release ZIP (audio + cover + metadata JSON/CSV/PDF)
  5. Upload the ZIP package to your chosen distributor (CDBaby, Symphonic, etc.)

Editing Metadata

Admin can edit any release's metadata after approval - go to the release detail page and click Edit Metadata. You can update title, ISRC codes, UPC, credits, and more. Useful for correcting errors before pushing to a distributor.

Copyright Scanner (ACRCloud)

To prevent users from uploading copyrighted tracks (which could lead to takedowns and platform bans), Distro Supawave fingerprints every uploaded master audio file through the ACRCloud audio recognition API before it is permanently stored.

How It Works

  1. An artist uploads a track - the audio is chunked and stitched into a master file
  2. Distro Supawave extracts a short ~15 second snippet (no FFmpeg required) and sends it to ACRCloud
  3. ACRCloud fingerprints the snippet and matches it against a library of commercial recordings
  4. If a match is found, the track is marked blocked and the release shows a Flagged badge in the admin queue
  5. The uploader’s account is also flagged for review

Configuration

ACRCloud provides a free developer tier (100 identifications per month). To enable the scanner:

  1. Create a free project at console.acrcloud.com
  2. Copy your project’s Access Key, Access Secret, and Host (shown in the ACRCloud console)
  3. Add them to your .env file:
ACR_PROJECT_KEY=your_access_key
ACR_PROJECT_SECRET=your_access_secret
ACR_HOST=https://identify-eu-west-1.acrcloud.com

Use the exact host from your ACRCloud project console (e.g. identify-eu-west-1.acrcloud.com, identify-ap-southeast-1.acrcloud.com). Then reload the app.

The admin Settings → Payment page shows a live ACRCloud Copyright Scanner status card (Enabled / Disabled) with the exact keys you need to add. Scanning runs automatically on every upload - no per-track action is required.
Note: ACRCloud is a recognition API - it does not store or list the files you upload. If you want to match your own catalogue, add your tracks to the project’s Custom Music DB in the ACRCloud console.

Royalties & CSV Import

When your distributor sends you a royalty report (usually monthly), you upload it to Distro Supawave. The platform parses the CSV, matches tracks to the correct artists, and creates earnings records for each artist.

Supported CSV Formats

  • Soundrop - select "Soundrop" format when uploading
  • Auto-detect - select "Auto" and the system will detect column headers automatically. This works with most major distributor CSV formats.

How to Import a Royalty Report

  1. Go to Royalties → Reports in the admin panel
  2. Click Upload CSV Report
  3. Select the distributor format (Soundrop or Auto)
  4. Select your CSV file and click Upload
  5. The system processes each row, matches artists by name, and creates earnings records
  6. Any unmatched artists are shown in the success message so you can investigate
Duplicate Prevention: Each CSV file is hashed on upload. Uploading the same file twice will be detected and rejected automatically.

Artist Matching

The system matches CSV rows to artists using this priority order:

  1. ISRC code (most accurate)
  2. UPC code
  3. Track title + artist name (fuzzy match)

If no match is found, the row is skipped and the artist name is shown in the unmatched list.

Earnings & Approvals

After importing a CSV, all earnings are created with a Pending status. The admin must approve earnings before they are credited to an artist's wallet.

Approving Earnings

  1. Go to Royalties → Earnings Report
  2. Review pending earnings - each row shows artist, track, month, and amount
  3. Click Approve on individual earnings, or use Mass Approve to approve all selected
  4. Approved earnings are immediately added to the artist's wallet balance
  5. The artist can now request a withdrawal

Exporting Earnings Reports

You can export a monthly earnings CSV for any artist:

  1. Go to Royalties → Stream Reports
  2. Filter by artist, year, and month
  3. Click Export CSV to download, or Send to Artist to email the report directly
Only approved earnings are included in exported reports. Pending or rejected earnings are excluded.

Withdrawals

Artist Withdrawal Request

Artists can request a withdrawal once they have approved earnings in their wallet. They go to the Wallet page, enter the amount, and select a payout method:

  • PayPal (enter PayPal email)
  • Bank Transfer (enter bank account details)
  • Cryptocurrency (enter wallet address)

Admin Processing Withdrawals

  1. Go to Withdrawals → Pending
  2. Review the request - artist name, amount, and payout method are shown
  3. Process the payment manually through your payment provider
  4. Click Approve - the artist is notified by email
  5. Or click Reject with a reason - the amount is returned to the artist's wallet
Distro Supawave does not process withdrawals automatically. You must manually send the payment to the artist through PayPal, your bank, or your crypto exchange, then mark it as approved in the platform.

Streaming Stats

Streaming stats are populated from the royalty CSV imports. Artists can view their stats from the Streaming Stats page in the user dashboard.

Stats Flow

  1. Artist visits Streaming Stats - sees all their releases listed with total streams
  2. Clicks View Stats on a release - sees all tracks in that release
  3. Clicks Details on a track - sees full breakdown: store-by-store streams, top countries, monthly trend chart

Manual Stream Entry (Admin)

Admin can also manually add streaming data without uploading a CSV - useful for adding streams from a distributor that does not provide CSV reports. Go to Analytics → Manual Stream Entry, select the track, month, year, and enter streams per store.

Available Filters

  • Date range - Last 30 Days, Last 3 Months, Last 6 Months, Last 12 Months, This Year, All Time
  • Store - filter by individual streaming platform

Getting Your API Keys

  • PayPal: developer.paypal.com/dashboard
  • Paystack: dashboard.paystack.com
  • CoinPayments: coinpayments.net
  • NowPayments: account.nowpayments.io

NowPayments — IPN Secret (required)

The NowPayments IPN Secret is used to verify every payment callback. It is required — without it, the application rejects callbacks and successful payments will not activate the subscription.

  1. Log in to account.nowpayments.io and go to Settings → Account.
  2. Copy your IPN Secret (also called the callback/notification secret). If none is shown, create a random secret (e.g. a 32-character string).
  3. Set your IPN callback URL to https://yourdomain.com/webhook/nowpayments.
  4. Paste the secret into Settings → Payment → NowPayments → IPN Secret in the admin panel and save.
  5. Copy the API Key from NowPayments and enter it in the API Key field.

PayPal — Webhook Setup (required)

In addition to the Client ID and Client Secret, PayPal requires a Webhook ID to verify webhook signatures. Payments cannot be confirmed without it.

  1. Log in to developer.paypal.com and open your App.
  2. Copy the Client ID and Client Secret (sandbox or live) and enter them under Settings → Payment → PayPal.
  3. Click Add Webhook (or Edit Webhook) and set the Webhook URL to https://yourdomain.com/webhook/paypal.
  4. Subscribe to the CHECKOUT.ORDER.APPROVED event (keep the default event subscriptions).
  5. After saving, copy the generated Webhook ID and paste it into the Webhook ID field in the admin payment settings.
You can enable or disable individual gateways from the payment settings page. Only enabled gateways are shown to users at checkout.

Frequently Asked Questions

Does Distro Supawave automatically push music to Spotify or Apple Music?

No. Distro Supawave is a management platform. You download the release package and manually upload it to your chosen distributor (CDBaby, Symphonic, DistroKid, etc.). This gives you full control over which distributor you use and keeps the platform lean and fast.

Can I use my own distributor?

Yes. Distro Supawave works with any distributor. The metadata export (JSON, CSV, PDF) is designed to be compatible with all major distributors.

What CSV formats does the royalty importer support?

Distro Supawave has a built-in Soundrop parser and a universal auto-detect parser that works with most distributor CSV formats by detecting column headers automatically.

Can I run this on shared hosting?

Yes. Distro Supawave is fully compatible with shared hosting (cPanel). The audio upload uses chunked uploading to work within standard PHP upload limits.

Does Distro Supawave check for copyrighted uploads?

Yes. Every upload is fingerprinted through ACRCloud (see Copyright Scanner). Matches are flagged in the admin release queue so you can reject them before they are distributed. ACRCloud offers a free tier of 100 identifications per month.

Can I customise the landing page without editing code?

Yes. Use Website → Homepage Content in the admin panel to edit all landing page text, images, features, pricing text, featured artists, and call-to-action (see Homepage Content).

How do I update Distro Supawave when a new version is released?

Download the new version from your marketplace/vendor, back up your current files and database, then overwrite the files (excluding .env) and run php artisan migrate via SSH or the cPanel terminal.

Can I change the platform name and branding?

Yes. Go to Settings → General to update the site name, logo, and favicon. All emails and pages will reflect your branding automatically.

The installer is showing a requirements error. What do I do?

Contact your hosting provider and ask them to enable the missing PHP extension. All required extensions are standard and available on most modern hosting plans.

I uploaded a CSV but some artists were not matched. Why?

The system matches CSV rows to artists by ISRC, UPC, or track title. If the artist name or track title in the CSV does not match exactly what is in the platform, the row will not match. Check the unmatched list shown after the import and ensure artist names and track titles match.
